# dig log: メニューバーポップアップでのスライダー設定とモデル切替

## 目的・前提・制約
- 目的: メニューバーアイコンをクリックしたときに開くポップアップウィンドウに Expert cache と Context を表示し、スライダーで変更できるようにする。設定画面もスライダーでよい。Context のスライダーは「いい感じのステップ」にする。モデルも変更できるようにする。
- 前提（実装済み、`docs/plans/archived/2026-10-14-strata-menubar.md`）: MenuBarExtra は `.menu` スタイル。設定は UserDefaults に保存し、次回起動に反映。稼働中は「保存のみ」と「停止して反映」を選べ、自動再起動はしない。稼働中の実設定（`RunningInfo.settings`）と保存済み設定を区別する。モデルは Q2_0 専用（`model_name == qwen3.8-flash-next-q2_0` を導入確認で要求）。実行用 JSON は `~/Library/Application Support/StrataMenubar/strata-q2_0.run.json`。
- 確認した事実（2026-10-15）:
  - `~/Dev/local/Strata` にある設定は `strata-q2_0.json` と `run-q2_0.sh` のみ。`Strata-data/models` は `Q2_0` のみ、`packs` は `q2_0` のみ。
  - Strata の setup は `--model Q2_0|IQ2_XS|IQ3_XXS|IQ3_S`（Mac docs では `Q2_0|IQ3_XXS|IQ3_S|UD-Q4_K_XL|UD-Q5_K_XL|UD-Q6_K_XL`）、`--family qwen|swift`、`--context N`（PC の既定 32768）を受け、モデルごとに `strata-<model>.json` と `run-<model>.sh` を書く。32 GB の Mac では experts を SSD からストリームする。
  - エンジンの `--max-context` は整数。モデルの最大コンテキストは 262,144（docs/DETAILS.md）。PC 向け setup の既定は 32768、8K 超では KV キャッシュ精度 `--kv`（既定 int8）が関わる。M5 Max では 4K / 32K トークンのプロンプトで計測されている。この Mac（32 GiB）で検証済みなのは 8192 のみで、ベース設定に `--kv` 指定はない。
  - 前回の Plan の対象外: Strata のインストール・更新・モデル取得、他モデル対応。今回「モデル変更」を扱うため、「他モデル対応」の対象外は見直し対象。
  - Strata 本体のモデル管理（setup.py / docs/MAC.md）: モデルは setup 時に `--model` で選び、GGUF を `Strata-data/models/<MODEL>/` に取得、pack（tokenizer・dense.bin・expert profile）を `Strata-data/packs/<model>/` に作り、モデルごとに `strata-<model>.json` と `run-<model>.sh` を Strata ディレクトリ直下へ書く。複数モデルは同じ Strata ディレクトリに共存でき、更新時は全 `strata-*.json` を順に扱う。`--setup` で別モデルの追加や設定変更を行う。サーバープロセスは `--config` で渡した1モデルだけを提供し（`/v1/models` も1件）、モデルの切替はサーバーの停止・別設定での起動を意味する。`~/.config/strata/settings.json` には `data_dir` と `installs`（Strata ディレクトリ一覧）だけが記録される。`--context` も setup 時に `--max-context` として JSON に固定される。
- 制約: Strata 本体・モデル・Pi 設定をアプリから書き換えない（維持）。

## 決定事項
- モデルの選択は、Strata ディレクトリにある setup 済みの `strata-<model>.json` の一覧から選ぶ。モデルの取得と setup はアプリが行わず、ユーザーが `setup.sh` で行う。Q2_0 専用のチェックは外し、選んだベース JSON から実行用コピーを作る。
  - 理由: Strata 本体・モデルを書き換えない制約を保ち、setup 済みのものだけが選べるので起動失敗の経路が増えない。
  - 出典: Q1 → A
- 設定画面に、別モデルを取得・導入するための setup コマンドを案内し、コピーできるようにする。
  - 出典: Q1 の回答で追加要望
- 案内のモデル一覧は docs/MAC.md の Mac 向け一覧（Q2_0 / IQ3_XXS / IQ3_S / UD-Q4_K_XL / UD-Q5_K_XL / UD-Q6_K_XL、ダウンロード容量と必要メモリの目安）をアプリに固定で持ち、ポップアップメニューで選ぶとコマンドが組み上がる。導入済みのものには印を付ける。コマンドの形は `cd "<Strataの場所>" && ./setup.sh --setup --model <MODEL> --no-start`（`--no-start` は setup が自分でサーバーを起動しないため。`--yes` は付けず、setup の質問と注意をユーザーが見られるようにする）。
  - 理由: コピーして実行するだけにしたい目的に合い、容量の目安で 32 GiB に無理なモデルを選びにくい。一覧が古くなっても起動経路（setup 済み JSON の一覧）には影響しない。
  - 出典: Q2 → A
- 導入済みモデルの切替は、ポップアップと設定画面の両方に置くポップアップメニューで行う。選ぶと保存され（次回起動に反映）、稼働中なら「未反映」表示と「停止して反映」で適用する。自動再起動はしない。
  - 理由: ポップアップを「よく触る操作がそろう場所」にし、キャッシュ・コンテキストと同じ保存・反映ルールにそろえる。
  - 出典: Q3 → A
- Context スライダーは 2 の累乗の 6 段: 1024 / 2048 / 4096 / 8192 / 16384 / 32768。8192 超と 2048 未満の警告は維持する。
  - 出典: Q4 → B（最初の回答 A を撤回）
- Expert cache スライダーは 1 GB 刻み、下限 1 GB、上限は実行中の Mac の物理メモリ量（GiB、32 GiB の Mac なら 32）。上げ下げはユーザーの自己責任とし、スライダーでは禁止しない。警告は出す（閾値の決め方は Q7）。設定画面の注記には「この Mac では 5 GB で起動時のフットプリント約 13 GB」という実測を事実として書く。
  - 出典: Q5・Q6 の回答（Q6 は A を基に上限を物理メモリ全量へ、警告は維持に変更）
- 警告の閾値: Expert cache は「物理メモリの 50% 超」（32 GiB なら 17 GB 以上）と「2 GB 未満」（約 0.8 GB で失敗、プロンプト用 1.36 GB が必要という実測）で警告し、文言に割合・実測の根拠を添える。Context の警告は「8192 超は未検証でメモリ増」「2048 未満は Pi の maxTokens 2048 が入らない」の事実ベース文言を維持する。
  - 理由: 「半分」は一言で説明でき、他の Mac でも意味が変わらない。
  - 出典: Q7 → A
- メニューバーアイコンのクリックで開くのは今のメニュー（MenuBarExtra `.menu` スタイル）のままにする。`.window` スタイルのポップアップウィンドウにはしない。
  - 出典: Q8 の回答（「今のメニューでいい。ウィンドウじゃなくて」）
- メニューは SwiftUI のまま、「Model ▸」「Expert cache ▸」「Context ▸」のサブメニューに選択肢を並べ、選ぶと保存される（Model は導入済み `strata-*.json` の一覧、Expert cache は 1 GB〜物理メモリ量の 1 GB 刻み、Context は 1024〜32768 の 2 の累乗 6 段）。稼働中に保存値が実設定と異なれば従来どおり「未反映」表示と「Stop and Apply」。スライダーは設定画面だけに置く。
  - 理由: 今のメニューを保ちながらクリック2回で値を変えられ、AppKit への作り直しを避ける。
  - 出典: Q9 → B
- 設定画面は下書き方式にする: スライダー・モデル・ポート・ディレクトリは下書きを編集し、「Apply」で保存する（検証エラーがあれば Apply 不可）。「Revert」で下書きを保存値に戻す。未適用の変更があるままウィンドウを閉じようとしたら破棄確認ダイアログ（Discard Changes / Keep Editing）を出す。稼働中は「Apply and Restart Server」（保存して再起動）を置き、保存済み設定が実設定と異なるときは従来の「Stop and Apply Saved Settings」。メニューのサブメニューは選んだ時点で保存（変更なし）。保存は次回起動に反映されるだけで、稼働中のサーバーには明示の再起動操作まで何も起きない（自動再起動なしは維持）。
  - 理由: 即時保存ではテキスト欄の未確定入力の扱い（閉じたときに保存されるか破棄か）が曖昧になるため、ユーザーが Apply 方式に変更。
  - 出典: implement 中のユーザー決定（Q10 の A を置換）
- 破棄確認は、ウィンドウを閉じるときだけでなくアプリ終了（⌘Q）のときも出す（Keep Editing なら終了を取り消す）。ダイアログの既定ボタンは Keep Editing、Discard Changes は破壊的ボタンとして表示する。
  - 出典: implement 中のユーザー決定（レビューの decision required 2件）

- 実装の細部（Q11 で合意）:
  - モデルの識別子は設定ファイルの stem（`strata-q2_0.json` → `q2_0`）を設定に保存し、表示は JSON の `model_name` を使う。実行用 JSON は `strata-<tag>.run.json`。保存済みの識別子に対応する JSON がなくなっていれば、導入済み一覧を添えてエラーにする。未保存時の既定は `q2_0` があればそれ、なければ一覧の先頭。
  - 導入確認は `model_name == qwen3.8-flash-next-q2_0` の要求を外し、選んだ JSON に `model_name`・`exe`・`args`・各ファイルがあることだけを確認する。
  - 案内の固定一覧は docs/MAC.md の表（pack、GPU がマップするファイルの容量、必要メモリの目安、推奨 RAM）と setup.py のダウンロード容量を転記する。
  - Pi の注記は「モデルを変えると `/v1/models` のモデル ID（`model_name`）が変わるので、`models.json` の `id` も合わせる」を加える。
  - 出典: Q11 → A
