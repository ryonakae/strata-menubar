# Model Detection, Download and Removal Implementation Plan

dig log: [docs/dig/2026-10-16-model-detection-and-install.md](../dig/2026-10-16-model-detection-and-install.md)（決定事項・対象外・確認した Strata の事実・計画で扱う制約の正本）

## Requirements

導入済みモデルの一覧をディレクトリの変化に追従させ、モデルの取得（Strata の setup の実行）・進捗表示・中止・初回起動時の準備・削除をアプリの中で行えるようにする。守るもの: 自動再起動しない、アプリが起動していないサーバーは止めない、127.0.0.1 のみ、クライアント設定に触れない、所有するプロセスグループだけに信号を送る、取り残したプロセスを引き取らない。

- **検出**: 導入済み（Strata ディレクトリ直下の `strata-<tag>.json`）とダウンロード済み（データディレクトリの `models/<MODEL>/`）の一覧を監視対象の状態にし、Strata 直下・`models/`・各 `models/<MODEL>/` のファイルシステム監視、設定画面を開いたとき・Check・Strata ディレクトリの入力変更・アプリの処理完了時の読み直しで更新する。更新ボタンは置かない。
- **取得**: `.venv/bin/python setup.py --setup --model <MODEL> --no-start --vision no` を、サーバーと同じ `PosixProcessLauncher`（posix_spawn、専用プロセスグループ、stdin は /dev/null、stdout/stderr は `~/Library/Logs/StrataMenubar/setup.log` へ追記）で起動する。同時に走らせるのは 1 つ。Strata 側への書き込みは setup 自身が行い、アプリ本体は書かない（削除を除く）。
- **サーバーとの独立**: Download はサーバーの状態に関係なく開始でき、ダウンロード中もサーバーの起動・停止・再起動は自由。setup の出力に `=== Step 6: preparing the model for Strata ===` が現れた時点でサーバー（External Strata 含む。idle unload で一時的にエンジンが落ちている Running も含む）が動いていれば、アプリがプロセスグループに SIGINT を送って止め、モデルを「Downloaded（初回起動時に準備）」として扱う。サーバーが止まっていれば setup はそのまま準備まで進み、モデルは「Installed」になる。
- **初回起動時の準備**: ダウンロード済み（設定 JSON なし、全 shard に `.done`）のモデルを選んで Start / Stop and Apply Saved Settings / Apply and Restart Server を押したら、停止 → 同じコマンドで setup を再実行（ダウンロードはスキップされ準備だけ行う）→ サーバー起動、を一続きに行う。準備中は Starting の状態行に「preparing <model>…」と出し（Starting なので Start は押せない）、準備の時間は起動の 600 秒に数えない。準備が失敗したらサーバーは起動せず Error にして `setup.log` を案内する。準備中の Stop は setup のグループへ SIGINT。
- **進捗**: ダウンロード中（Step 5）は `setup.log` の `\r  <file>: X.XX / Y.YY GB (NN%)` から割合（全 shard 合計: `.done` 済み shard のディスク上の大きさ + 現在の shard の受信量を、カタログの download_gb で割る）、他のステップは `=== Step N: title ===` の段階名を不確定バーで出す。設定画面の Models 節に進捗バーと Cancel、メニューに 1 行（例: 「Downloading IQ3_S: 45% (37.6 / 83.6 GB)」「Preparing IQ3_S…」）。完了・中止・失敗は次のジョブまでメニューの同じ行に残し、失敗時はログを案内する。
- **中止と終了**: Cancel はグループに SIGINT、出なければ SIGTERM（20 秒）→ SIGKILL（10 秒）。途中のファイルは残し、次の Download（同じコマンド）が続きから再開する。setup 実行中の Quit は確認（「ダウンロード中です。終了すると止めます。次回は続きから再開できます」）。Quit なら止めてから終了、Cancel なら終了しない。サーバーも動いていれば 1 つのダイアログにまとめる。setup を残したまま終了しない。
- **停止と失敗の区別**: 終了コードではなくファイルの状態で判定する。設定 JSON があれば Installed、全 shard に `.done` があれば Downloaded、ユーザーの Cancel なら Cancelled、それ以外は失敗（ログ末尾の `[X]` 行を表示）。
- **ディスク**: Download の前に見積もり（download_gb + experts コピー（arena_gb、ストリーミングする Mac で RAM が 96 GB 未満のときだけ）+ UD 系は repack ファイル（shard1_gb）+ pack 約 1.5 GB）とデータディレクトリの空きを表示し、空きが「見積もり + 10 GB」未満なら Download を無効にして理由を出す。ストリーミング判定は setup と同じ式（`shard1_gb + 8 > ram_gb × 0.75 × 1.073741824`、64 GB 以上の Mac は `min(それ, ram_gb × 1.073741824 × 0.7)` と比べる。`ram_gb` は物理メモリの GiB）。メモリ不足では止めない。
- **端末で動いている setup**: アプリが起動したジョブのプロセスグループに属さない `setup_mac.py` のプロセスがある間は「in progress elsewhere」として、そのコマンドラインの `--model <NAME>` のパック（`--model` がなければ全パック）の Download と Delete を無効にする。判定は `pgrep -fl setup_mac.py` で、一覧の読み直しのたびに行う（`.part` の mtime や `.preparing.lock` では、pip・エンジン再ビルド・shard の検証中や、アプリ自身の Cancel 直後を正しく判定できない）。引き取らない。
- **削除**: 各モデル（Installed / Downloaded / Partially downloaded）に Delete。消す対象をファイルと合計サイズで列挙して確認し、ゴミ箱へ移動する（完全削除しない）。対象は設定 JSON の `--pack` / `--native` / `--ple-gguf` から辿る: `--pack` のディレクトリ、`--native` と `--ple-gguf` のファイルとその隣の `<name>.done` / `.experts` / `.experts.done` / `.part` / `.repack.lock`、カタログのモデルディレクトリ `models/<MODEL>/`（あれば一式）、`strata-<tag>.json`、`run-<tag>.sh`、`strata-<tag>.log`、アプリの `strata-<tag>.run.json`。`--expert-profile` など共有物（`data/expert-profile.bin`、`mtp/`、mmproj、`build-metal/`、`.venv`、`metal/` ディレクトリ自体）は触らない。そのモデルが稼働中（アプリのサーバーの `model`、External Strata の `model` が `model_name` と一致、または準備中）、そのパックのジョブ中、in progress elsewhere の間は無効。保存済みの選択モデルを消しても設定は触らず、既存の「(not installed)」表示に任せる。ゴミ箱では空きが増えないことを空き容量の横に書く。
- **設定画面**: 「Model」節と「Install another model」節を「Models」節に統合する。先頭に起動するモデルのピッカー（Installed は `model_name`、Downloaded は「<MODEL> (downloaded; prepared at the first start)」）。カタログの 6 パックを 1 行ずつ、状態（Installed / Downloaded / Downloading NN% / Preparing / Partially downloaded (N GB) / Not downloaded / 失敗）、サイズの案内（ダウンロード、GPU がマップする容量、必要メモリ、推奨 RAM、ディスク消費の見積もり）、操作（Download または Resume / Cancel / Delete）。末尾に空き容量と Open Setup Log。Copy Command と `SetupCommand` は削除する。Download / Delete は保存済みの Strata ディレクトリに対してだけ有効（下書きのディレクトリが保存値と違う間は無効にし、Apply を促す）。
- **メニュー**: ジョブの 1 行（押すと設定画面）と、ログの並びに「Open Setup Log」。Model の行は一覧の状態から名前を引く。
- **ドキュメント**: README の Use / Settings / Installing another model / Limitations、AGENTS.md の不変条件（「アプリ本体は Strata checkout・モデルファイルに書かない。書くのは明示操作で起動した Strata の setup と、確認のうえゴミ箱へ移す削除だけ」「setup は `--setup --model --no-start --vision no` で、ダウンロードと初回起動時の準備にだけ実行する」）と Layout。Download がエンジンの再ビルド（checkout が変わっていた場合）を伴いうることを README に書く。
- **作業の順序**: 無関係な未コミット変更（Context 262144 への拡張、`Assets.xcassets`）は着手前に別コミットにし、`default.profraw` は追跡しない。検出（部分 1）を最初のタスクにする。
- **対象外**: 画像入力（`--vision no` 固定）、`--update` / `--build` / `--context` などダウンロード以外の setup オプション、同時ダウンロード、Strata 本体の導入・更新、端末で始めた setup の引き取り、独自ダウンローダー、自動再起動、外部サーバーの停止、クライアント設定の書き換え。

## Implementation Decisions

- **カタログ**（`StrataModelCatalog.swift`）: `ModelPack` に `family`（`.qwen` / `.unsloth`）、`shards`（2 / 2 / 2 / 4 / 6 / 6）、`expertsCopyGB`（setup.py の `arena_gb`: 34.0 / 42.9 / 50.3 / 77.0 / 98.4 / 109.2）を足す。`tag` は `(unsloth ? "unsloth-" : "") + name.lowercased()`（現状の `name.lowercased()` は UD 系で `strata-unsloth-ud-q4_k_xl.json` に合わない既存バグ）、`directoryName` は `(unsloth ? "unsloth-" : "") + name`、`shardNames` は qwen 系 `Qwen3.8-Flash-Next-GSQ-RCO-<NAME>-0000i-of-00002.gguf`、UD 系 `Qwen3.8-Flash-Next-<NAME>-0000i-of-0000n.gguf`。`streams(memory: MemoryBudget) -> Bool` と `diskEstimateGB(memory:) -> Double`（download + (unsloth ? mappedFileGB : 0) + (streams && GiB < 96 ? expertsCopyGB : 0) + 1.5）、`requiredFreeGB = estimate + 10`。`pack(forTag:)`。`SetupCommand` は `SetupPlan.make(installation: StrataInstallation, pack: ModelPack, log: URL) -> LaunchPlan` に置き換える（executable `installation.python`、引数 `[setup.py, "--setup", "--model", pack.name, "--no-start", "--vision", "no"]`、cwd はルート、環境は `PYTHONUNBUFFERED=1` を足したもの、`standardOutputLog` は `paths.setupLog`）。
- **データディレクトリ**（新設 `StrataMenubar/Strata/StrataDataDirectory.swift`）: setup の `data_folder()` と同じ解決: `$XDG_CONFIG_HOME/strata/settings.json`（既定 `~/.config`）の `data_dir`、なければ `<root>/../Strata-data`。設定ファイルの URL は注入できるようにしてテストで実際の `~/.config` を読まない。`models` / `packs` / `metal` の URL、`modelDirectory(for pack)`、空き容量（存在する最も近い親の `volumeAvailableCapacityForImportantUsage`）。
- **パックの状態**（`StrataDataDirectory` に `packState(for:)`、`enum PackFilesState { notDownloaded, partial(bytes: Int64), downloaded }` と `busyElsewhere(for:) -> Bool`）: ディレクトリがない、または `.gguf*` が 1 つもなければ notDownloaded。全 `shardNames` に `<name>.done` があり `.part` がなければ downloaded。それ以外は partial（ディレクトリ内の `.gguf` と `.part` の合計バイト）。
- **端末の setup の検出**（`ModelLibrary` の `refresh()` 内、新設 `ExternalSetup.running(excludingGroup: pid_t?) -> [ExternalSetup]`）: `Foundation.Process` で `/usr/bin/pgrep -fl setup_mac.py` を実行し、各行の pid と引数を読む。`getpgid(pid)` がアプリのジョブのプロセスグループ（`installer.job?.pid`、閉包で渡す）と同じものは除く。引数の `--model <NAME>` があればそのパックだけ、なければ全パックの `busyElsewhere` を true にする。
- **一覧**（新設 `StrataMenubar/Strata/ModelLibrary.swift`、`@MainActor @Observable`）: `root`（保存済み設定の Strata ディレクトリ）、`installed: [InstalledModel]`、`packs: [PackStatus]`（カタログ順。`enum PackStatus.State { installed(InstalledModel), downloaded, partial(bytes:), notDownloaded }` + `busyElsewhere`）、`freeBytes: Int64?`、`dataDirectory`。`refresh()` は同期の読み直し（`installedModels()` + `packState`）。監視は新設 `DirectoryWatcher`（`DispatchSource.makeFileSystemObjectSource` を `O_EVTONLY` の fd に、mask は `.write/.delete/.rename/.extend`、300 ms のデバウンスで main の `refresh()`）。対象は root、`<data>/models`、存在するカタログのモデルディレクトリ。`refresh()` のたびに監視を組み直す（新しいディレクトリ、消えたディレクトリ）。`update(root:)` で保存先が変わったら組み直す。`launchProblems(for tag:) -> [String]`: installed なら `installation.check(model:)`、downloaded なら空（準備は起動時）、それ以外は既存の「config is missing / Installed: …」の 1 件。`ModelLibrary.scan(root:)`（静的、監視なし）を設定画面の未保存ディレクトリの表示に使う。
- **setup の出力の解釈**（新設 `StrataMenubar/Strata/SetupOutput.swift`、純粋）: `struct SetupOutputParser { mutating func feed(_ text: String) -> [SetupEvent] }`。`\n` と `\r` の両方で区切り、最後の未完行は次の feed に持ち越す。イベント: `.step(number: Int, title: String)`（`=== Step N: title ===`）、`.shardProgress(name: String, haveBytes: Int64, totalBytes: Int64)`（正規表現 `^\s*(\S+): +([\d.]+) / ([\d.]+) GB \((\d+)%\)`、GB × 1e9）、`.alreadyDownloaded(name)`（`[ok] <name> already downloaded`）、`.failure(message)`（`[X]  message`）、`.stopped`（`stopped.`）。
- **インストーラ**（新設 `StrataMenubar/Strata/ModelInstaller.swift`、`@MainActor @Observable`）: 依存は `ProcessLaunching`、`AppPaths`、`ModelLibrary`、`serverIsRunning: @MainActor () -> Bool`（AppContainer が「`serverManager.state` が `.stopped` / `.failed` 以外、または `serverManager.ownsProcess`（停止に失敗して所有が残っている）」なら true と結線）、`Timing`（ログのポーリング 500 ms、SIGTERM 20 s、SIGKILL 10 s。テストでは短く）。状態: `job: InstallJob?`（`pack`、`purpose: .download / .prepare`、`phase: SetupPhase`（`.checking(title)` = Step 1〜4、`.downloading`、`.preparing`、`.writingConfig`）、`progress: (have: Int64, total: Int64)?`、`pid`、`cancelRequested`）と `lastOutcome: InstallOutcome?`（`.installed(pack)` / `.downloaded(pack)` / `.cancelled(pack)` / `.failed(pack, message)`。次のジョブ開始で消える）。`statusLine: String?`（メニューと設定画面が同じ文字列を使う）。
  - `download(_ pack:) async`: ジョブ中・installed・busyElsewhere なら何もしない（UI が先に無効化する。ここは最後の守り）。`LogStore` で `setup.log` をローテートし、開始時のファイル長をオフセットに記録、`SetupPlan` で起動、500 ms ごとに新しいバイトを読んで parser に渡す。`.step(6, _)` を受けたとき `serverIsRunning()` なら `signalGroup(SIGINT)` して `stoppedForServer` を立てる。プロセス終了後に `library.refresh()` し、結果をファイルの状態で判定する（上記の優先順）。
  - `prepare(_ pack:) async throws`: 同じ起動で `purpose = .prepare`、Step 6 の割り込みはしない（呼び出し元がサーバー停止を保証する）。結果が `.installed` でなければ `InstallError.failed(message)` / `.cancelled` を投げる。ジョブ中なら `InstallError.busy` を投げる。
  - `cancel()`: `cancelRequested = true`、`signalGroup(SIGINT)`、終了を待ち、出なければ SIGTERM → SIGKILL（`ServerManager.cleanupGroup` と同じ段取り。共通化はしない: 所有の単位が違う）。
  - `ownsProcess`、`quitDescription: String?`（「A download of IQ3_S (PID N) is running」）。
- **起動に含める準備**（`ServerManager`）: `@MainActor protocol ModelPreparing: AnyObject { func needsPreparation(model tag: String) -> Bool; func prepare(model tag: String) async throws; func cancelPreparation() }` を `ModelInstaller` が実装（needsPreparation = 設定 JSON がなく、カタログに tag があり、状態が downloaded）。`ServerManager.init` に `preparer: any ModelPreparing = NoPreparation()` を足す（既存テストはそのまま）。`StartingInfo` を `model: String`（起動する tag。Delete の稼働中判定に使う）+ `phase: StartingPhase`（`.preparing` / `.loading(pid: pid_t)`）+ `port` + `since` にし、`pid: pid_t?` は計算プロパティ。`performStart`: ポートの probe の後、`needsPreparation` なら `state = .starting(.preparing)` → `await preparer.prepare` → 成功なら従来の `makePlan` → spawn（`startupDeadline` は `awaitReadiness` が始まるときに計算されるので準備の時間は含まれない）。`InstallError.cancelled` なら `.stopped`、他の失敗なら `.failed("The model could not be prepared: <message>. See the setup log.")`。`canStop` は `.starting` なら `owned == nil` でも true。`stop()` は enqueue の前に `.starting(.preparing)` なら `preparer.cancelPreparation()` を呼ぶ（準備は start の operation の中で待っているので、キューに入れると詰まる）。`QuitRequirement` の `.starting(.preparing)` は `.confirmStop("Preparing <model> for its first start")`。
- **削除**（新設 `StrataMenubar/Strata/ModelFiles.swift`）: `struct ModelFiles { var items: [URL]; var totalBytes: Int64 }`。`forInstalled(_ model: InstalledModel, installation:, data:, paths:)` と `forDownloaded(_ pack:, data:)`（`models/<directoryName>`、あれば `packs/<tag>`、UD 系はあれば `metal/<tag>-metal.gguf` とその `.done` / `.repack.lock`）。列挙は要件の対象どおりで、`--expert-profile` は含めず、別の項目の中にある項目は落とす（`metal/` ディレクトリ自体は決して含めない）。他の導入済み設定 JSON が `--pack` / `--native` / `--ple-gguf` で指しているファイル・ディレクトリ（とその親のモデルディレクトリ）は共有物として落とし、そのモデル固有の `strata-<tag>.json` / `run-<tag>.sh` / `.log` / `.run.json` だけ残す（設定 JSON のコピーが同じモデルファイルを指す場合に、もう一方のモデルを消さないため）。サイズは項目ごとに合計（ディレクトリは再帰）。`trash(_:using: (URL) throws -> Void = FileManager.default.trashItem)` で項目ごとに移し、失敗は集めて投げる。確認ダイアログは `NSAlert`（項目の一覧と合計、「Move to Trash」が destructive、Cancel が既定）。実行後に `library.refresh()`。
- **終了**（`AppDelegate` / `QuitRequirement`）: `QuitRequirement.init(state:ownsProcess:download: String? = nil)` に拡張し（既存の呼び出しはそのまま）、`download` があれば state が `.stopping` / `.stopped` / `.external` / `.failed` でも `.confirmStop` を返し（今の `.waitForStop` は確認なしで止めに入るため）、サーバーの文があれば「The server … is running, and a download of IQ3_S is running」のように 1 文にする。`settleBeforeQuit` は先に `installer.cancel()` を待ち、それでも `installer.ownsProcess` なら既存の `confirmQuitLeavingProcess` と同じ扱いにし、そのあとサーバーを止める。確認ダイアログの説明文に「the next Download resumes where it stopped」を添える。
- **文言の差し替え**: `StrataInstallation.check(model:)` の「Run Strata's setup.sh --setup --model to add a model.」は「Download it in Settings › Models.」にする（メニューの「Cannot apply:」に出る）。
- **配線**（`AppContainer` / `StrataMenubarApp`）: `library`（root は `settingsStore.settings.strataDirectoryURL`。保存のたびに `update(root:)`）、`installer`、`serverManager` の `preparer` に installer。`MenuContent` と `SettingsView` に `library` と `installer` を渡す。
- **ログ**（`AppPaths.setupLog`、`LogStore`）: `rotateIfLarge` を `setupLog` にも使う（`prepareForSetup()`）。メニューの「Open Setup Log」は既存の `open(log:)`。
